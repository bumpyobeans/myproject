# 범표원두 커피 추천 시스템 — 4일차 발표용 첫 버전 작업 계획

## 목표

4일차 발표에서 **“고객과 재미있게 대화하면 범표원두의 실제 제품을 발견하게 되는 경험”**을 완성한다.

최종 데모 흐름:

**첫 화면 → 상담 시작 → 질문/답변 → 상황·취향 파악 → 제품 추천 → 추천 이유 → 새로운 커피 경험 제안 → 실제 범표원두 제품 표시 → 상담 데이터 저장**

회원가입은 만들지 않고, 저장 데이터는 연결된 Supabase를 사용한다.

---

## 0단계. 범위 고정

### 무엇을 만든다

- 발표에서 보여줄 핵심 사용자 시나리오 1개를 확정한다.
- 첫 버전 제품 범위를 대표 제품 중심으로 고정한다.
- 질문 수를 최소화하고 추천까지 빠르게 도달하도록 한다.

### 어떻게 확인한다

- 처음부터 끝까지 1명의 고객이 2~3분 안에 추천 결과까지 도달할 수 있는지 직접 테스트한다.
- “이 기능도 넣자”는 요청은 발표 이후 범위로 분리한다.

---

## 1단계. 범표원두 제품 카탈로그 만들기

### 무엇을 만든다

Supabase에 **범표원두가 실제 판매·보유하고 있는 제품만** 넣을 수 있는 구조를 만든다. 추천 대상은 외부 상품이 아니라 이 제품 카탈로그로 한정한다.

제품마다 최소한 다음 정보를 갖는다.

- 제품명
- 제품군
- 원두/제품 특징
- 맛 키워드
- 음용 방식
- 추천 상황
- 디카페인 여부
- 대표 이미지
- 상품 URL
- 추천 우선순위

### 어떻게 확인한다

- 화면이나 데이터 조회를 통해 대표 제품이 정상적으로 불러와지는지 확인한다.
- 예: 조선호랑이를 조회했을 때 제품명, 특징, 이미지, 추천 태그가 모두 나오는지 확인한다.

---

## 2단계. 첫 화면 만들기

### 무엇을 만든다

브랜드 철학을 전달하면서 상담을 시작할 수 있는 첫 화면을 만든다. 첫 화면부터 “어떤 커피를 살까?”가 아니라 “내게 맞는 범표원두를 찾아볼까?”라는 기대를 만든다.

핵심 문구:

> 맛있는 커피 만드는 건 전문가에게 맡겨.  
> 너희는 맛있게 즐기기만 해.

보조 문구:

> 재미있게 대화하면서 내 커피를 발견해보세요.

상담 시작 버튼을 배치한다.

### 어떻게 확인한다

- 첫 화면만 보고 처음 방문한 사람이 무엇을 해야 하는지 바로 이해하는지 확인한다.
- 상품 목록을 먼저 찾게 하지 않고 상담 시작으로 자연스럽게 이동하는지 확인한다.

---

## 3단계. 대화형 질문 흐름 만들기

### 무엇을 만든다

첫 버전에서는 다음 핵심 질문을 중심으로 상담한다.

1. 평소 커피를 어떻게 즐기는가?
2. 어떤 맛을 좋아하는가?
3. 싫어하거나 부담스러운 맛이 있는가?
4. 지금 어떤 상황에서 마실 커피를 찾는가?
5. 새로운 커피를 경험해볼 의향이 있는가?

고객 답변에 따라 불필요한 질문은 건너뛸 수 있게 한다.

### 어떻게 확인한다

- 고소한 취향 고객과 산미 취향 고객을 각각 테스트한다.
- 여행/캠핑과 선물 상황도 테스트한다.
- 모든 경로가 추천 결과로 도달하는지 확인한다.
- 질문이 너무 길거나 반복적으로 느껴지지 않는지 확인한다.

---

## 4단계. 범표원두 제품 추천 로직 만들기

### 무엇을 만든다

첫 버전에서는 AI가 범표원두 밖의 상품을 임의로 추천하지 않도록 하고, **범표원두 제품 카탈로그 안에서만** 추천하도록 만든다. 추천 기준은 범표원두가 가진 상담 기준을 명시적인 규칙으로 구현한다.

추천은 두 층으로 나눈다.

**A. 지금 가장 잘 맞는 제품**

- 고객의 상황
- 음용 방식
- 취향
- 회피 조건

을 조합해 1순위 제품을 선정한다.

**B. 새로운 경험 제품**

현재 취향과 너무 멀지 않으면서 한 단계 다른 맛을 경험할 수 있는 **범표원두 제품**을 선정한다.

### 어떻게 확인한다

최소 5가지 테스트 케이스를 만든다.

- 고소함 + 집에서 간편하게
- 산미 선호 + 핸드드립
- 산미 비선호 + 아메리카노
- 여행/캠핑
- 선물

각 케이스에서 추천 제품과 추천 이유가 의도대로 나오는지 확인한다.

---

## 5단계. 추천 결과 화면 만들기

### 무엇을 만든다

추천 결과에 다음 내용을 보여준다.

- **오늘의 추천 제품**
- 제품 이미지
- 제품명
- 맛의 특징
- 고객의 답변과 연결된 쉬운 추천 이유
- **새로운 커피 경험** 영역
- 새로운 경험 제품 이미지/제품명/이유
- 상품을 확인할 수 있는 버튼

핵심은 “제품 정보 나열”이 아니라 **“왜 나에게 이 커피를 추천했는지”**가 먼저 보이게 하는 것이다.

### 어떻게 확인한다

- 고객이 추천 제품을 보고 “왜 이걸 추천했는지” 바로 이해하는지 확인한다.
- 추천 제품과 새로운 경험 제품이 같은 제품으로 중복되지 않는지 확인한다.
- 실제 범표원두 제품 이미지가 깨지지 않고 표시되는지 확인한다.

---

## 6단계. Supabase 상담 데이터 저장

### 무엇을 만든다

회원가입 없이 상담 세션을 생성하고 다음 데이터를 저장한다.

- 세션 ID
- 상담 시각
- 질문/답변
- 취향/상황 태그
- 추천 제품
- 새로운 경험 제품
- 추천 결과 클릭 등 기본 행동 데이터

### 어떻게 확인한다

상담을 한 번 완료한 뒤 Supabase에서 해당 세션 데이터가 생성되는지 확인한다.

다음 테스트를 한다.

- 새로고침 후 새로운 세션이 구분되는가
- 서로 다른 고객의 상담이 섞이지 않는가
- 답변과 추천 결과의 연결이 유지되는가

---

## 7단계. 실제 범표원두 제품으로 연결하기

### 무엇을 만든다

추천 결과에서 **실제로 판매·보유 중인 범표원두 제품**을 확인할 수 있도록 연결한다. 제품명, 이미지, 설명, 상품 URL은 제품 카탈로그에서 가져온다.

발표에서는 반드시 **실제 제품이 화면에 등장하는 순간**을 강조한다.

### 어떻게 확인한다

- 추천 결과의 상품 버튼을 눌렀을 때 정확한 제품 페이지로 이동하는지 확인한다.
- 제품명과 이미지가 실제 판매 제품과 일치하는지 확인한다.

---

## 8단계. 발표용 시나리오 고정 및 테스트

### 무엇을 만든다

발표자가 직접 시연할 대표 고객 시나리오를 하나 고정한다.

권장 시나리오:

> “커피머신은 없고 집에서 아메리카노를 즐겨요. 고소한 맛을 좋아하고 산미는 별로 안 좋아해요.”

시스템은 고객에게 몇 가지 추가 질문을 한 뒤 **조선호랑이 드립백 같은 실제 제품을 추천**하고, 추천 이유와 새로운 커피 경험을 보여준다.

### 어떻게 확인한다

발표 당일 인터넷/데이터 상태가 좋지 않아도 시연이 중단되지 않도록 최소한의 데모 경로를 반복 테스트한다.

- 첫 화면에서 시작
- 질문에 답변
- 추천 결과 표시
- 제품 이미지 표시
- 추천 이유 표시
- 새로운 경험 표시
- Supabase 저장 확인

# 4일 운영 순서

## 1일차 — 설계와 데이터

- 범위 확정
- 제품 데이터 정리
- Supabase 테이블/데이터 구조 설계
- 대표 제품 데이터 입력
- 질문/답변 구조 확정

**완료 기준:** 제품과 상담 데이터가 구조화되어 있고 추천 로직을 구현할 준비가 됨.

## 2일차 — 핵심 사용자 경험

- 첫 화면
- 상담 화면
- 질문 흐름
- 답변 상태 관리
- 추천 로직 1차 구현

**완료 기준:** 고객 답변에 따라 추천 결과까지 이동하는 흐름이 작동함.

## 3일차 — 제품 추천 경험과 저장

- 추천 결과 화면
- 실제 제품 이미지
- 추천 이유
- 새로운 경험 제안
- Supabase 상담 데이터 저장
- 상품 페이지 연결

**완료 기준:** 상담부터 실제 제품 노출과 데이터 저장까지 한 번에 완료됨.

## 4일차 — 발표 버전 완성

- 대표 시나리오 고정
- UI 다듬기
- 문구 수정
- 제품 이미지 정리
- 오류 테스트
- 발표용 시연 리허설

**완료 기준:** 처음 보는 사람에게 2~3분 안에 서비스 가치를 보여줄 수 있음.

# 발표에서 보여줄 메시지

기술을 설명하는 발표가 아니라 고객 경험을 보여준다.

### 발표 흐름

**문제**

“온라인에서는 고객과 충분히 대화하기 어렵습니다.”

↓

**해결**

“그래서 범표원두 직원이 매장에서 하던 커피 상담을 온라인으로 옮겼습니다.”

↓

**경험**

“고객은 커피 전문가가 될 필요가 없습니다. 자신의 상황과 취향만 이야기하면 됩니다.”

↓

**결과**

“범표원두가 지금 가장 잘 맞는 커피를 찾아주고, 새로운 커피 경험까지 제안합니다.”

↓

**핵심 장면**

실제 범표원두 제품이 화면에 등장한다.

> 맛있는 커피 만드는 건 전문가에게 맡겨.  
> 너희는 맛있게 즐기기만 해.

---

# 발표 이후 확장 후보

- 고객의 구매 결과 연결
- 추천 후 만족도 수집
- 고객 취향별 추천 정확도 분석
- 추천 규칙 개선
- 제품별 전환율 분석
- 고객 재방문 시 이전 취향 활용
- 관리자용 추천 데이터 대시보드
- 장기적으로 GPTS의 추천 엔진으로 발전

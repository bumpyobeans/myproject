# 범표원두 커피 추천 시스템 — 설계 문서

## 1. 프로젝트 한 줄

**“맛있는 커피 만드는 건 전문가에게 맡겨. 너희는 맛있게 즐기기만 해.”**

커피를 좋아하는 고객이 자신의 취향과 커피를 즐기는 상황을 편하게 이야기하면, **반드시 범표원두가 현재 판매·보유하고 있는 제품 안에서** 잘 맞는 커피를 추천하고 그 이유를 쉽게 설명하며, 한 단계 새로운 커피 경험까지 제안하는 대화형 추천 서비스.

## 2. 해결하려는 문제

오프라인 매장에서는 직원이 고객에게 여러 질문을 하면서 취향과 상황을 파악하고 적합한 원두·제품을 추천할 수 있다. 반면 온라인에서는 고객이 충분히 질문을 이어가기 어렵고, 단순 상품 탐색만으로는 자신에게 맞는 제품을 찾기 어렵다.

반복되는 상담 기준은 크게 두 축이다.

- **취향:** 고소함, 산미, 균형, 깔끔함, 진함 등
- **상황/음용 방식:** 핸드드립, 아메리카노, 라떼·베리에이션, 여행·캠핑, 선물, 커피머신 보유 여부 등

또한 고객이 산미를 싫어한다고 해서 항상 산미 없는 커피만 권하는 것이 아니라, 현재 취향에 맞는 선택을 먼저 주고 부담 없이 새로운 산미나 새로운 커피 경험을 제안할 수 있어야 한다.

## 3. 핵심 사용자

- 커피를 좋아하고 범표원두 제품을 선택하려는 고객
- 회원가입 없이 이용
- 첫 버전에서는 누구나 바로 상담을 시작할 수 있도록 한다.

## 4. 핵심 경험

### 시작

첫 화면에서 상품 목록보다 **대화를 시작하도록 유도**한다.

메인 메시지:

> 맛있는 커피 만드는 건 전문가에게 맡겨.  
> 너희는 맛있게 즐기기만 해.

보조 메시지:

> 재미있게 대화하면서 내 커피를 발견해보세요.

### 상담

질문을 고정된 설문처럼 길게 나열하지 않고, 고객의 답에 따라 다음 질문을 선택적으로 이어간다.

예시:

1. 평소 커피를 어떻게 즐기는지
2. 어떤 맛을 좋아하는지
3. 싫어하거나 부담스러운 맛이 있는지
4. 지금 어떤 상황에서 마실 커피를 찾는지
5. 새로운 맛을 경험해볼 의향이 있는지

### 추천

추천 결과는 최소한 다음 세 가지를 제공한다.

1. **상황에 맞는 제품 추천**
2. **추천한 이유를 쉬운 말로 설명**
3. **새로운 커피 경험 제안**

추천은 “당신에게 맞는 **범표원두 제품**”과 “다음에 경험해볼 **범표원두의 다른 제품**”을 구분한다.

예:

- 지금 잘 맞는 커피: 조선호랑이
- 이유: 고소하고 묵직하면서도 산미가 완전히 사라지지 않아 편안하게 즐길 수 있음
- 다음 경험: 산미가 부담스러운 고객에게 역삼동호랑이처럼 상큼한 산미가 명확한 제품을 소량 경험하도록 제안

## 5. 추천의 기본 원칙 — 범표원두 제품 안에서 선택

이 서비스의 추천 대상은 **범표원두의 제품으로 한정**한다. 고객의 취향이나 상황에 맞는 일반적인 커피를 설명하는 것이 목적이 아니라, 그 조건에 가장 잘 맞는 **실제 범표원두 제품을 발견하게 하는 것**이 핵심이다.

따라서 추천 로직은 다음 순서를 따른다.

1. 고객의 상황과 음용 방식을 파악한다.
2. 범표원두가 보유한 제품군 중 이용 가능한 제품을 좁힌다.
3. 고객의 맛 취향과 회피 조건으로 제품을 좁힌다.
4. 범표원두 제품 중 가장 적합한 **1순위 제품**을 추천한다.
5. 현재 취향에서 한 단계 확장할 수 있는 **새로운 경험 제품**도 범표원두 제품 안에서 제안한다.
6. 추천 결과에는 실제 제품 이미지와 제품명, 쉬운 추천 이유를 함께 보여준다.

**외부 브랜드 제품이나 범표원두에 없는 제품을 추천하지 않는다.**

## 6. 첫 버전 제품 데이터 범위

업로드된 범표원두 자료를 기준으로 첫 버전에서 다룰 수 있는 대표 제품군은 다음과 같다.

### 원두 — 블렌딩 라인업

- 인도호랑이 — 호밀 같은 고소함, 묵직한 바디감
- 범프레소 — 다크 초콜릿의 묵직한 쌉쌀함과 단맛, 구운 아몬드의 고소함과 깊은 바디
- 조선호랑이 — 고소하고 묵직, 위트있는 산미
- 호랑이형님 — 잔잔한 산미, 굿 밸런스
- 역삼동호랑이 — 자몽의 씁쓸 새콤함, 살구 같은 과실의 산미
- 아프리카호랑이 — 리치 같은 달콤한 산미, 와인 같은 바디감

### 원두 — 싱글오리진 라인업

- 디카페인호랑이 — 호밀 같은 고소함, 브라운 슈거의 단맛
- 에티오피아 모모라 G1 — 잘 익은 딸기, 꿀의 바디, 마신 후 긴 여운
- 케냐 AA 카루만디 — 청정의 단맛과 자몽의 주시함, 풍부한 바디감

### 드립백

- 조선호랑이
- 호랑이형님
- 역삼동호랑이
- 디카페인호랑이

### 티백 커피

- 조선호랑이
- 호랑이형님
- 역삼동호랑이
- 디카페인호랑이

### 캡슐

- 퍼플_인도호랑이
- 실버_범프레소
- 레드_조선호랑이
- 골드_호랑이형님
- 그린_역삼동호랑이
- 블루_디카페인호랑이

### 파우더커피

- 인도호랑이 — 진하고 고소한 진한맛
- 조선호랑이 — 부드럽고 산뜻한 밸런스
- 호랑이형님 — 달콤고소 데일리 맛
- 역삼동호랑이 — 상큼깔끔 산미라인
- 디카페인호랑이 — 밤에도 편안한 깔끔고소

### 콜드브루

- 디카페인 콜드브루

## 7. 제품 선택 규칙의 초안

첫 버전에서는 복잡한 머신러닝 모델을 만들지 않는다. 범표원두가 이미 가진 상담 기준을 명시적인 추천 규칙과 제품 데이터로 구조화한다.

### 상황별 기본 연결

- 핸드드립 → 원두 중심 추천
- 아메리카노를 간편하게 → 드립백 또는 티백
- 여행·캠핑 → 휴대·간편 제품 우선
- 커피머신 보유 + 캡슐 사용 → 캡슐
- 라떼·베리에이션 → 파우더커피 등 활용성이 높은 제품
- 콜드브루를 원하는 상황 → 콜드브루
- 선물 → 사용 장비가 없는 사람도 즐길 수 있는 간편커피 제품 우선

### 취향별 기본 연결

- 고소함/묵직함 → 인도호랑이, 조선호랑이 등
- 균형/잔잔한 산미 → 호랑이형님
- 산뜻하고 상큼한 산미 → 역삼동호랑이
- 산미를 좋아하면서 과실감이 뚜렷한 경험 → 아프리카호랑이, 에티오피아 모모라 G1, 케냐 AA 카루만디 등
- 디카페인 필요 → 디카페인호랑이 계열

위 규칙은 **초기 상담용 가설**이다. 실제 고객 상담 데이터가 쌓이면 추천 결과와 구매/만족 데이터를 비교해 규칙을 개선한다.

## 8. 회원가입과 고객 데이터

회원가입은 만들지 않는다.

대신 상담 시작 시 익명 세션을 만들고, 상담 과정과 추천 결과를 Supabase에 저장한다.

첫 버전에서 저장할 데이터 예시:

- 상담 세션 ID
- 상담 시작/종료 시각
- 고객이 선택하거나 답한 음용 방식
- 취향 정보
- 싫어하는 맛/회피 정보
- 사용 상황
- 커피머신 보유 여부
- 새로운 경험 제안에 대한 반응
- 추천 제품
- 추천 이유
- 추가로 제안한 제품
- 고객의 추천 결과 클릭 여부
- 구매 링크 클릭 여부

**주의:** 이름, 전화번호, 이메일 등 불필요한 직접 식별정보는 첫 버전에서 수집하지 않는다. 고객 데이터를 축적하는 목적은 개인을 식별하기보다 **취향·상황·추천·반응 데이터를 분석하는 것**이다.

## 9. Supabase 역할

Supabase는 첫 버전의 데이터 저장소로 사용한다.

권장 논리 구조:

- `sessions` — 상담 세션
- `answers` — 고객의 질문 답변
- `recommendations` — 추천 결과
- `products` — 범표원두 제품 정보
- `product_tags` 또는 제품 속성 — 맛/상황/음용방식 등의 추천 태그

제품 데이터는 코드 안에 흩어놓기보다 데이터로 분리해두는 방향을 우선한다. 그래야 이후 대표님이나 팀이 제품 정보를 수정해도 추천 로직 전체를 다시 고칠 필요가 줄어든다.

## 10. 개인정보/운영 원칙

- 회원가입 없음
- 첫 버전은 최소한의 익명 상담 데이터만 저장
- 민감하거나 직접 식별 가능한 개인정보는 수집하지 않음
- 고객의 답변을 추천 개선에 활용할 수 있도록 구조화
- 실제 운영 전에는 개인정보 처리방침과 Supabase 접근정책(RLS)을 별도로 검토

## 11. 발표용 핵심 시나리오

발표에서 보여줄 핵심 장면은 **“대화가 끝난 뒤 실제 범표원두 제품을 딱 보여주는 순간”**이다.

발표자는 “커피를 추천하는 AI”가 아니라 **“범표원두 안에서 나에게 맞는 제품을 찾아주는 커피 경험 서비스”**로 소개한다.

권장 시나리오:

> 고객: 커피머신은 없고 평소 아메리카노를 좋아해요.  
> 고객: 고소한 맛을 좋아하고 산미는 별로 안 좋아해요.  
> 시스템: 평소에는 어떤 상황에서 커피를 드세요?  
> 고객: 집에서 편하게 마셔요.
>
> **추천: 조선호랑이 드립백**
>
> “고소하고 묵직한 맛이 중심이라 지금 좋아하시는 맛에 잘 맞아요. 드립백이라 머신 없이도 향을 충분히 즐길 수 있어요.”
>
> **그리고 한 가지 새로운 경험을 추천해드릴게요.**
>
> “산미가 강한 커피가 부담스러우셨다면, 바로 강한 산미부터 시작하지 않고 조금 더 균형 잡힌 커피부터 경험해보세요.”

최종 화면에서는 실제 범표원두 제품 이미지, 제품명, 추천 이유, 새로운 경험 제안을 함께 보여준다.

## 12. 첫 버전에서 하지 않을 것

- 회원가입/로그인
- 결제 기능
- 복잡한 개인화 AI 모델 학습
- 모든 범표원두 상품의 완벽한 자동 분류
- 관리자 대시보드 전체 구현
- 고객별 장기 CRM 자동화
- 재고/주문 시스템 연동
- 네이버 스마트스토어 주문 데이터 자동 연동

4일차 발표 이후 확장한다.

## 13. 성공 기준

첫 버전은 다음 흐름이 실제로 끝까지 작동하면 성공으로 본다.

**첫 화면 → 대화 시작 → 최소 질문 → 상황/취향 파악 → 추천 → 추천 이유 → 새로운 경험 제안 → 실제 제품 노출 → 상담 데이터 Supabase 저장**

기술보다 이 사용자 경험이 끊김 없이 작동하는 것이 우선이다.

# 카페 키오스크 매출노트

CUBE_CENTER(카운터 포스 + 키오스크)와 O2POS Web(키오스크)의 매출 보고서를 불러와 매출·메뉴·시간대 데이터를 한 화면에서 보고, 매출을 올릴 아이디어를 자동으로 뽑아 주는 대시보드입니다.
설치할 것 없이 `index.html` 파일 하나를 브라우저로 열면 됩니다.

## 볼 수 있는 것

| 화면 | 내용 |
|---|---|
| 핵심 지표 | 메뉴 판매액, POS 실매출, 객단가, 선불카드 충전·사용·잔액 (이전 같은 기간 대비 증감) |
| 매출 상승 아이디어 | 선불 잔액·적립 구조, 행사 할인, 키오스크 쏠림, 디저트 동반 구매, 원두·홈카페, 옵션 업셀, 선불카드, 포장 비율, 피크·한산 시간, 약한 요일, 메뉴 정리 후보 |
| 매출 추이 | 일별 / 월별(자료가 있는 모든 달) 전환, 매출처별 누적 막대 (메뉴 판매액 / POS 실매출), 특이사항 점선 표시 |
| 특이사항 · 전후 비교 | 신메뉴, 명절·휴무, 키오스크 화면 변경, 행사, 가격 변경을 적어 두면 전후 7/14/28일을 요일을 맞춰 비교 |
| 키오스크 비교 | 매출 비중, 주문 수, 객단가, 바쁜 시간, 최다 판매 메뉴 |
| 시간대별 평균 | 하루 기준 시간별 매출 / 주문 수 |
| 요일 × 시간 지도 | 요일·시간별 하루 평균 매출(칸에 만원 단위 숫자), 가장 바쁜 칸 표시, 요일별 하루 합계, 시간별 평균 막대, 휴무 요일 자동 표시 |
| 메뉴별 판매 순위 | 수량, 판매액, 비중, 키오스크별 비율, 선불 결제 비율, 행사 할인율, ABC 등급 |
| 상품군별 매출 | 음료 · 베이커리 · 원두·홈카페 · 옵션 · 선불카드, 키오스크별 |
| 옵션·업셀 지표 | 매출처별·월별 아이스 사이즈업 비율, 샷추가·디카페인 100잔당, 1잔당 옵션 매출(목표 55% · 5번 · 500원 대비), 많이 팔린 유료 옵션 |
| 선불카드 현황 | 충전, 적립 포인트, 사용 포인트, 잔액 변화, 현금 환산 |
| 행사 할인이 나간 메뉴 | 선불 사용을 뺀 할인액, 할인율 |

위쪽에서 기간(하루 / 7일 / 30일 / 전체 / 직접 선택)과 매출처(전체 / CUBE 카운터 / CUBE 키오스크 / O2POS 키오스크)를 고를 수 있습니다.

## 함께 쓰기 (구글 드라이브 + 공유 자료)

claude.ai에서 열면 대시보드는 **공유 자료**로 동작합니다. 사장님과 초대받은 직원이 모두 같은 화면을 봅니다.

1. 직원은 매일 마감 후 POS 파일 4개를 구글 드라이브 폴더 **「범표원두 POS 매출자료」** 에 넣습니다.
   - CUBE: **상품상세** 1개
   - O2POS: **일자별 매출**, **시간대별 매출**, **상품별 매출현황** 3개 (상품별은 순위 기준을 **‘전체’**로)
   - 파일 이름은 바꾸지 않아도 됩니다. 날짜가 파일 안에 없는 O2POS 상품별 매출현황은 올린 시각으로 영업일을 추정합니다(한국 시각 정오 전이면 전날). 날짜별 하위 폴더를 만들어 넣어도 됩니다.
2. 구글 드라이브를 연결한 사람이 대시보드를 열면 폴더의 **새 파일만** 가져와 공유 자료에 반영합니다. ‘지금 불러오기’ 버튼으로도 됩니다. 같은 파일은 두 번 들어가지 않습니다.
3. 드라이브를 연결하지 않은 직원도 자료는 그대로 봅니다. 파일을 대시보드에 직접 올려도 공유 자료에 반영됩니다(공유 권한이 ‘참여자’ 이상일 때).
4. 월 단위로 묶인 자료가 있는 달에 하루치 자료가 들어오면 겹쳐서 지우지 않고 기록에 이유를 남깁니다.

파일을 브라우저로 직접 열면(claude.ai 밖) 예전처럼 그 브라우저에만 저장됩니다.

## 특이사항 · 전후 비교

신메뉴 출시, 명절·휴무, 키오스크 이미지 변경, 행사 같은 일을 날짜와 함께 적어 두면 그 일이 매출에 준 영향을 자동으로 계산합니다. 공유 자료로 열면 직원도 같이 보고 적을 수 있습니다.

- **계속되는 변화** (신메뉴·키오스크·행사·가격·기타)
  - 비교 기간: 그날 전 N일과 그날부터 N일을 비교합니다. N은 7/14/28일 중 고릅니다.
  - 요일 맞춤: 후 기간의 하루하루를 전 기간 같은 요일 평균과 비교합니다. 그래서 일요일이 몇 번 들어갔는지에 따라 결과가 흔들리지 않습니다.
  - 지표: 하루 메뉴 판매액, 주문 수, 객단가, 음료 100잔당 디저트, 주문당 메뉴 수, 많이 늘거나 준 메뉴.
  - 키오스크처럼 일부 매출처에만 해당하면 나머지 매출처의 같은 기간 변화와 비교합니다. 그 차이(%p)를 그 일만의 효과로 보여 줍니다.
  - 신메뉴에 ‘관련 메뉴’ 글자를 넣으면 그 글자가 들어간 메뉴의 판매량과 비중을 따로 보여 줍니다. 기존 음료가 줄었는지도 함께 보여 줍니다.
- **명절·휴무**
  - 직전 4주 같은 요일 평균을 ‘평소’로 삼아 명절 전, 명절 당일, 명절 후를 비교합니다.
  - 평소 영업하던 요일에 쉬었다면, 그날 평소 매출만큼을 휴무로 덜 팔린 금액으로 추정합니다.
- 명절·휴무로 적은 날은 다른 특이사항을 비교할 때 자동으로 뺍니다.
- 주·월 단위 상품 자료는 영업일 비율로 나눠 쓰므로 메뉴 지표는 근사값입니다. 일별 상품 자료가 있으면 정확합니다.

## 두 가지 매출

선불카드는 5만원 이상 충전 시 10%, 50만원 이상 충전 시 20%를 추가 적립하고, 사용할 때는 POS에서 메뉴를 찍은 뒤 100% 할인으로 처리합니다. 그래서 POS 합계만 보면 매출이 왜곡되므로 두 가지로 나눠 봅니다.

| | 계산 | 뜻 |
|---|---|---|
| **POS 실매출** | 할인 뺀 결제 금액 | 실제로 들어온 돈. 선불 충전은 포함, 선불로 먹은 음료는 0원 |
| **메뉴 판매액** | POS 실매출 − 선불 충전 + 선불 사용 | 실제로 나간 메뉴 값. 메뉴 분석·목표는 이 값 기준 |

- **선불 사용** = POS의 100% 할인 금액. 선불 결제는 직원이 받는 카운터 포스(CUBE에 합산)에서만 되므로 ‘할인금액 − 단품 할인’(주문 할인)을 선불 사용으로 보고, O2POS 키오스크 할인은 모두 행사 할인으로 봅니다.
- **행사 할인** = 나머지 할인(CUBE 단품 할인, ‘원두구매시 음료할인’ 같은 음수 줄).
- 적립 규칙과 키오스크별 선불 사용 기록 방식은 데이터 관리 › 선불카드 설정에서 바꿀 수 있습니다.

## 데이터 넣는 방법

POS 화면의 엑셀 저장 기능으로 받은 파일(.xlsx / .xls / .csv)을 화면 맨 아래 **데이터 관리**에 끌어다 놓으면 됩니다. 여러 파일을 한 번에 올려도 하나씩 확인 후 불러옵니다.

매출처는 셋으로 나눠 봅니다: **CUBE 카운터**, **CUBE 키오스크**, **O2POS 키오스크**.

| POS | 받을 파일 (한 달에 한 번씩) | 쓰이는 곳 |
|---|---|---|
| CUBE_CENTER | **상품상세** 1개 | 주문 한 줄마다 일자·시간·판매번호·할인·매장/포장·**주문POS**가 있어서 이 파일 하나로 메뉴·시간대·일별·객단가·선불 사용이 다 나오고, 카운터와 키오스크가 자동으로 나뉩니다 |
| O2POS Web | **일자별 매출**, **시간대별 매출**(날짜×시간 표), **상품별 매출현황**(조회 조건의 순위 기준을 반드시 **‘전체’**로) 3개 | 일별 추이·객단가, 요일×시간 지도, 메뉴 순위 |

- CUBE의 상품 분석·상품 시간대 분석도 읽을 수 있지만 카운터+키오스크 합산이라 ‘CUBE 카운터’로 들어갑니다(키오스크분 포함). 상품상세를 쓰면 필요 없습니다. 한 달치 합계 파일은 불러올 때 그 달의 1일~말일을 넣고, 매출 추이를 ‘월별’로 보면 됩니다.
- 상품상세의 취소·반품 줄은 판매금액이 0원이라 빼고, 선불 사용은 카운터의 ‘전체할인’, 행사 할인은 ‘단품할인’으로 봅니다.

- **순위 제한 경고:** O2POS 상품별 매출현황을 ‘상위 N위’ 제한을 건 채 받으면 판매가 적은 메뉴·옵션이 빠집니다. 이때 세 곳에서 알려 줍니다.
  - 파일을 불러올 때: 점유율 합계가 100%에 못 미치면 경고합니다. 드라이브 불러오기 기록에도 ⚠로 남습니다.
  - 데이터 관리의 ‘자료 점검’: 저장된 상품별 합계가 같은 기간 일별 매출보다 적은 곳을 모두 보여 줍니다.
  - 메뉴 순위 위: 지금 보는 기간에 빠진 매출을 보여 줍니다.
  - 매출 합계는 일별 자료 기준이라 영향이 없습니다. 순위 제한 없이 다시 받은 파일을 올리면 자동으로 교체됩니다.
- 형식을 자동으로 알아봅니다. CUBE 파일과 O2POS 파일을 알아서 구분해 두니 확인만 하면 됩니다.
- 파일 안에 조회 날짜가 없는 자료는 불러올 때 기간을 넣습니다. 한 번 넣은 기간은 다음 파일에 그대로 채워집니다.
- 매출은 할인을 뺀 **실매출(부가세 포함)** 으로 맞춥니다. CUBE는 ‘매출 금액’을 쓰고, O2POS는 ‘총매출 − 할인금액’으로 계산합니다.
- CUBE의 분류 소계 줄(예: ‘원두’, ‘빵/아슈크림’)과 ‘17 Lines’ 합계 줄은 자동으로 빼고, 소계 금액이 맞는 상품에는 그 분류 이름을 붙입니다.
- 두 POS의 분류 이름이 달라서, 메뉴 이름으로 **음료 / 베이커리 / 원두·홈카페(원두·홈카페·캡슐·병 커피·티백) / 옵션·기타 / 선불카드**로 다시 묶습니다. VIP카드 같은 선불카드와 ICE-UP·비닐봉투 같은 옵션은 메뉴 순위에서 뺍니다.
- 한 달치 상품 자료와 일별 자료를 함께 올리면, 일별 차트의 메뉴 판매액은 그날 실매출에 그 달의 비율을 곱해 나눕니다. 휴무일((미)영업일)은 빼고 계산합니다.
- 파일 이름에 “9월”처럼 달이 있으면 그 달 1일~말일(이번 달이면 어제까지)로 기간을 채웁니다.
- 같은 키오스크·같은 날짜를 다시 올리면 기존 자료를 **교체**하므로 중복되지 않습니다.
- 한 날짜에 일별·상품별·시간대별 자료가 함께 있으면 매출은 일별 > 상품별 > 시간대별 순서로 하나만 써서 두 번 더하지 않습니다.
- 주문 한 건마다 한 줄씩 있는 주문 내역 파일도 불러올 수 있습니다(상품별·시간대별·일별로 자동 집계).
- 데이터는 **그 브라우저에만** 저장됩니다. 원본 엑셀 파일은 따로 보관해 두세요.

처음 열면 예시 데이터(가상의 8주치 기록)가 보입니다. 화면 오른쪽 위에 “예시 데이터”라고 표시되고, 내 파일을 불러오면 바로 바뀝니다.

## 매출 기획에 쓰는 순서 (추천)

1. **매일** 마감 후 CUBE 상품상세 1개, O2POS 3개 파일을 드라이브 폴더에 넣는다.
2. **요일 × 시간 지도**에서 비어 있는 시간대를 찾고 → 그 시간 한정 프로모션을 기획한다.
3. **선불카드 현황**에서 잔액이 계속 쌓이는지 보고, 잔액 많은 단골에게 선결제 시스템의 전화번호로 방문 안내를 보낸다.
4. **메뉴 순위의 C등급**은 첫 화면에서 빼거나 계절 메뉴로 교체한다.
5. 2~4주 뒤 같은 기간을 비교해(핵심 지표의 ▲▼) 효과를 확인한다.
